## 1. KRITIEK — Account-overname via `users.upsert`

**Bestand:** [convex/users.ts](convex/users.ts) — `export const upsert = mutation({...})`
**Aanroeper:** [src/hooks/use-current-user.ts:27](src/hooks/use-current-user.ts#L27)

Dit is een **publieke** Convex-mutation zonder enige auth-check. De comment in de handler zegt:

```ts
// Called by Clerk webhook - auth handled by Clerk, no user-level auth needed
```

Dat klopt niet: hij wordt vanuit de **browser** aangeroepen (`useMutation(api.users.upsert)`), met volledig client-gecontroleerde argumenten. Een publieke Convex-mutation is aanroepbaar door iedereen die de deployment-URL kent — ook zonder in te loggen.

**Aanvalspad 1 — overname van een bestaand account:**

```
users.upsert({ clerkId: "<clerk-id van aanvaller>",
               email:   "<e-mail van directie-gebruiker>",
               name:    "x" })
```

De handler zoekt bij een onbekende `clerkId` door op e-mail (`by_email` index) en doet dan `ctx.db.patch(existing._id, { clerkId: args.clerkId, ... })`. Het bestaande bedrijfsaccount wordt daarmee **herbonden aan de Clerk-identiteit van de aanvaller**. Alle offertes, klanten, facturen en HR-gegevens van dat bedrijf zijn vanaf dat moment van de aanvaller.

**Aanvalspad 2 — privilege-escalatie:**

```ts
if (isAdminEmail(args.email) && !isAdminRole(existing.role)) {
  updates.role = "directie";
}
```

`args.email` is client-input. Wie een e-mailadres van de adminlijst opgeeft, krijgt de rol `directie` toegewezen.

**Aanbevolen fix**

1. Maak er een `internalMutation` van en roep hem aan vanuit de Clerk-webhookroute (server-side, met Svix-signatuurverificatie) — hetzelfde patroon dat `src/app/api/webhooks/resend/route.ts` al gebruikt.
2. Als de client-side sync moet blijven bestaan: haal `clerkId`, `email` en `name` uit `await ctx.auth.getUserIdentity()` in plaats van uit `args`. Nooit uit argumenten.
3. Verwijder de e-mail-fallback-lookup, of laat hem alleen bestaande records *lezen* — nooit `clerkId` overschrijven op basis van client-input.
4. Voeg een regressietest toe: "upsert met andermans e-mail mag de clerkId niet patchen".

## 2. HOOG — Cross-tenant datalekken (multi-tenancy)

Het datamodel scopet per `userId` (het bedrijfsaccount). Op deze plekken ontbreekt die scope, terwijl er wél `requireAuth` staat — de gebruiker is dus ingelogd, maar ziet data van **andere bedrijven**.

| Locatie | Probleem |
|---|---|
| [convex/weekPlanning.ts:98](convex/weekPlanning.ts#L98), `:255`, `:346`, `:445` | `query("medewerkers").filter(isActief === true).collect()` — geen `userId`-filter. Retourneert álle actieve medewerkers van álle bedrijven. |
| [convex/medewerkers.ts:723](convex/medewerkers.ts#L723) (`getWithStats`) | Urenregistraties worden gematcht op **medewerker-naam** (string), zonder tenant-scope. Twee bedrijven met een "Jan de Vries" delen elkaars uren. Bovendien een full table scan. |
| [convex/medewerkers.ts:804](convex/medewerkers.ts#L804), `:818` (`getMedewerkersMetPrestaties`) | `query("urenRegistraties").collect()` en `query("voorcalculaties").collect()` — volledige tabellen, alle tenants. |
| [convex/chat.ts:494](convex/chat.ts#L494) | `direct_messages` zonder tenant-scope. |
| [convex/users.ts:1035](convex/users.ts#L1035), `:1341`, `:1894` | `users` / `medewerkers` zonder scope. |

**Onderliggende oorzaak:** de tabellen `urenRegistraties`, `voorcalculaties` en `direct_messages` hebben **geen `userId`-veld** in [convex/schema.ts](convex/schema.ts). Tenant-scoping loopt indirect via `projectId`, wat bij naam-matching wegvalt.

**Aanbevolen fix**

1. Voeg `userId` toe aan `urenRegistraties`, `voorcalculaties` en `direct_messages` + een `by_user`-index; backfill via een migratie.
2. Vervang alle naam-matching door `medewerkerId` (het veld bestaat al als optioneel in het schema — maak het verplicht).
3. Vervang de `.filter((q) => …)`-scans door `.withIndex("by_user", …)`.
4. Overweeg een gedeelde helper (`scopedQuery(ctx, tabel)`) zodat vergeten scoping structureel onmogelijk wordt.

## 3. HOOG — Publieke Convex-functies zonder guard

Naast `users.upsert` staan deze functies open. Convex-`query`/`mutation`/`action` = publiek endpoint.

| Functie | Risico |
|---|---|
| [convex/standaardtuinen.ts](convex/standaardtuinen.ts) `get` | `ctx.db.get(id)` zonder auth of ownership-check. |
| [convex/projectKosten.ts](convex/projectKosten.ts) `getBudgetStatus` | Geen auth. Lekt **budget, kosten en margestatus** per `projectId`. |
| [convex/dagkaart.ts](convex/dagkaart.ts) `berekenReistijdenVoorDag` | Publieke `action` zonder auth die de Google Maps API aanroept → kostenmisbruik door derden. |
| [convex/emailLogs.ts](convex/emailLogs.ts) `updateFromWebhook` | Documenteert zichzelf als "webhook-only, security via Svix", maar is publiek → iedereen kan delivery-/bounce-/open-events vervalsen. Moet `internalMutation` zijn. |
| [convex/configuratorAanvragen.ts](convex/configuratorAanvragen.ts) `create` | Bewust publiek (websiteformulier), maar **zonder rate limiting** → spam/DoS. `offerteMessages.sendFromCustomer` doet dit wél goed via `checkPublicOfferteRateLimit`. Trek dat patroon door. |

**Correct opgelost, ter referentie:** `offerteMessages.listByToken` / `sendFromCustomer` (share-token + expiry-validatie + rate limit) en `materiaalDelta.*` (`veldToegang`). Gebruik die als sjabloon.

## 4. MIDDEL — Dark mode is stuk in 89 bestanden

`next-themes` is actief ([src/components/providers/theme-provider.tsx](src/components/providers/theme-provider.tsx)) en er zit een themawissel in de command palette en de sidebar. Dark mode is dus een echte, bereikbare feature.

- **4158** hardcoded Tailwind-kleurklassen (`text-gray-500`, `bg-green-100`, …) in **241** bestanden, in plaats van design-tokens (`text-muted-foreground`, `bg-card`, …).
- **89 bestanden** gebruiken hardcoded lichte kleuren en hebben **geen enkele `dark:`-variant** → onleesbare tekst en witte vlakken in dark mode.
- **33×** `bg-white` zonder `dark:`-tegenhanger.

Zwaarst getroffen, en juist publiek zichtbaar:

- de complete **configurator-flow** (`src/app/(public)/configurator/**` — gazon, verticuteren, bedankt, status, layout);
- **portaal-authenticatie** (`portaal/(auth)/registreren`, `portaal/(auth)/koppelen`) — het eerste wat een klant ziet;
- delen van **instellingen** (normuren-, factoren-, herinneringen-tab, debiteurenladder) en de factuur-workflow.

**Aanbevolen fix:** vervang per bestand door semantische tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `border-border`, `bg-card`). Statuskleuren (groen/rood/amber) verdienen eigen tokens — bijv. `--success`, `--warning`, `--danger` — in `globals.css`, zodat ze in beide thema's kloppen. Begin bij de publieke configurator.

## 5. LAAG — Aandachtspunten, geen blokkers

- **Client-zwaarte:** 462 van 555 `.tsx` zijn `"use client"` (83%); 84 van 85 `page.tsx` zijn client components. Grotendeels inherent aan Convex `useQuery`, maar het kost SSR/streaming en bundle. Kandidaten voor server components: pagina's die alleen layout en statische tekst renderen.
- **Ontbrekende laadstatussen:** 54 routes zonder `loading.tsx`; slechts 3 `error.tsx` (auth, dashboard, public). Sub-routes zoals `projecten/[id]/factuur` vallen terug op de parent-boundary.
- **108× `console.*`** in `src/` — Sentry is geconfigureerd; log liever daarheen.
- **Query-efficiëntie:** 80× `.filter((q) => …)` in plaats van `withIndex`, en 109 query-chains met `collect()`/`take()` zonder index. Een deel zit in `migrations.ts` (eenmalig, prima); de rest groeit mee met de data.
- **32 lussen met ≥2 db-calls** (N+1), o.a. `servicemeldingen.ts:220/264/266`, `garanties.ts:49`, `verlof.ts:102`, `materiaalDelta.ts:91`. Batch waar mogelijk met een `Map`-lookup.
- **8 openstaande TODO's**, waarvan twee functioneel relevant: [src/app/api/mollie/webhook/route.ts:162](src/app/api/mollie/webhook/route.ts#L162) (betalingsstatus wordt niet naar Convex geschreven) en [src/app/api/calendly/route.ts:13](src/app/api/calendly/route.ts#L13) (afspraken worden alleen gelogd, niet opgeslagen).

## 6. Voorgestelde volgorde

1. **`users.upsert` dichtzetten** (§1) — dit blokkeert alles; een productie-deploy met dit gat open is niet verantwoord.
2. **`emailLogs.updateFromWebhook` → `internalMutation`** en de vier ongeguarde functies uit §3 afdekken — klein werk, direct effect.
3. **Rate limit op `configuratorAanvragen.create`** — hergebruik `checkPublicOfferteRateLimit`.
4. **Tenant-scoping repareren** (§2) — begin met `weekPlanning` (grootste blootstelling, kleinste fix), daarna het schema-migratiewerk voor `urenRegistraties`/`voorcalculaties`.
5. **Dark mode in de publieke configurator** (§4) — klantgezicht.
6. Rest van §4 en de punten uit §5 als opruimwerk tussendoor.

Punten 1 t/m 3 zijn samen naar schatting een halve dag en halen het grootste deel van het risico weg.
